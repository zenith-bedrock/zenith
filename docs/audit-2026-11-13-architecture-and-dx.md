# Architecture and DX audit (2026-11-13)

Taken after the `Player` split (`5d645d9`). Method: reading code, greps and one full test run (1341/1341). **Not verified:** no live server run and no smoke run for this audit; no retail client. Findings are open work unless marked otherwise.

## What holds up
- `ArchitectureBoundaryTests` pins, at IL level: Packets reference no domain/protocol layer; Gameplay references no wire models, `Session` or `Protocol`.
- Nothing under `Packets/` references `Player`. Gameplay has no real `lock` (concurrency stays at the handoff edges).
- Largest domain file is `InventorySystem` (694 lines). `Player` went from 947 lines to identity/pose/inventory/vitals plus `Intents`, `Dig`, `Windows`, `Effects`, `Replicated` (`docs/architecture.md`, "Player").
- A clean build (`--no-incremental`) has 0 warnings (an earlier version of this audit said so from incremental builds, which hid 11; fixed).

## Findings, most serious first

1. **[DONE] A test-only parallel API lived in production code.** Removed: `TryFromLegacyFlat`, `ChestBase`/`CraftUiBase`/`CraftResultFlat`, the `Is*Flat` helpers, the `int` overloads of `InventoryStackAction.Transfer/Swap/Drop`, `TryToWire`, `DescribeForWire`, `MatchesAdvertisedStackNetId`, the flat `SendItemStackResponseOk`, `SendChestContent(x,y,z)`, `FloorDropStore.AddOrMerge`, and the unused `MaxSurfaceRise`/`BiomeCellSize`; ~90 test call sites now name slots with `InventorySlotReference`. The fire-and-forget wrappers are gone too: `ChestStore.Ensure` is deleted (gameplay uses `TryEnsure`), `World.SetBlock` is now a setup-time API that throws on a SoftCap refusal instead of dropping the edit. Found and fixed on the way: `ChestStore.TryLoadFromBlob` (hydrate) went through the SoftCap-gated `Ensure`, so at the cap it threw `KeyNotFoundException` instead of loading the saved chest; `InventoryProtocol.SendChestContent` mutated the chest store (a Protocol layer writing gameplay state); opening a chest whose cell could not be created showed a window that rejected every move, now the open is refused. Tests: `ChestStoreSoftCapTests`. Not changed on purpose: ignored `_ = Try...` results in `DamageableActorCombatCore` (ADR §135, a kill is never vetoed by loot capacity) and the projectile spawn at cap. Original finding:  The flat-slot scheme (`InventorySlotReference.TryFromLegacyFlat`, `InventoryContainerMap.ChestBase=100`/`CraftUiBase=200`/`CraftResultFlat`, `InventoryStackIntent`'s `Legacy(flat)` helpers, the `int flat` overloads of `DescribeForWire`/`MatchesAdvertisedStackNetId`) is documented as "compatibility only for characterization tests" yet is called from 6 places in `src/zenith` (4 in `InventoryProtocol`). It contradicts the no-legacy rule and leaves two ways to name a slot. Fix: migrate the tests (about 20 direct uses plus the helper callers) to `InventorySlotReference`, delete the flat API.
2. **DONE (2026-11-13) — The test suite was serial by configuration.** `src/zenith.Tests/xunit.runner.json` has `parallelizeTestCollections: false`; summed test time (139 s) is almost the wall time (2m16s). Three terrain tests alone take about 24 s. First find the shared static state or timing that motivated the flag, then enable parallelism (this is the way into open item 6). The lifecycle race fixed in `5d645d9` is the kind of test the serial mode hid. Outcome: `parallelizeTestCollections: true` (suite ~1m20 vs ~2m10); the process-wide statics `Blocks`/`Tools`/`BlockLoot` now publish an immutable generation through one `volatile` reference (a real product race, not just a test one) and their `ResetForTests` hooks are gone; tests that mutate process env or measure wall-clock time share `[Collection(ExclusiveCollection.Name)]`; deadline waits that depend on CPU-bound terrain generation or socket start-up have generous early-return timeouts. 6/6 consecutive full runs green after the last fix.
3. **DONE (2026-11-13) — `IntentContractTests.cs` was 3957 lines / 159 tests in one file.** Split into `BlockIntentTests`, `InventorySystemIntentTests`, `InventoryTransactionIntentTests`, `ItemStackRequestIntentTests`, `ChunkStreamIntentTests`, `MovementIntentTests`, `ChatAndGameModeIntentTests`, with the shared helpers in `IntentTestHelpers` (the harness stays in `IntentTestFixture.cs`). Test count unchanged (1349).
4. **[DONE] Stale text after ADR §149** (comments fixed; superseded notes added to ADRs 106, 107, 131, 132, 135). Original finding: `ChunkSpatialIndex`, `GroundMobMovement`, `FishSystem` still mention a "legacy actor/roster" and `IDamageableActor`/`FishStore`, which no longer exist. `docs/decisions.md` entries (§131 and others) describe `GroundMobCombat`/`IDamageableActor` without marking them superseded.
5. **`Player` surface.** `PlayerWindows.OpenChest` and `InventoryWindowOpen` still describe themselves as "compatibility projections": make them real API or remove them (count callers first). `Player` has 19 public setters (pose, vitals, flags) that by the single-writer rule only the GameLoop should write, with nothing enforcing it.
6. **Decision records.** 253 "ADR §" references in code; `docs/adr/` holds 3 files while `decisions.md` (3548 lines) holds the rest in one document. Hard to navigate and maintain.

## Suggested order
1 and 4 together (one commit), then 2 and 3, then 5, then 6.
