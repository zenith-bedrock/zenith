# ADR §146 — Crafting runs on the real vanilla recipe set, matched by shape, name and tag

> Part of the [decision log](README.md). Code and docs cite this record as `ADR §146`.

**Problem:** `RecipeRegistry` was seventeen hand-written *shapeless* recipes compared by aggregate item counts. A chest (a ring of eight planks) crafted from any eight planks, a stick from two planks side by side, extra items in the grid were ignored, and the client — which receives the real recipes — predicted crafts the server refused or the reverse. The embedded `recipes.nbt` (behaviour-pack JSON, legacy names, un-expanded) was never consumed and is not what goes on the wire.

**Choice:** the source of truth is the data BDS itself loads — the layered `vanilla*` behaviour packs (`.brarchive`, later version replaces earlier; see `tools/bedrock-data/BdsPack.cs`) — reduced by `bedrock-data recipes` (`tools/bedrock-data`, C#) to `src/zenith/data/recipes.json.gz` (≈1.1k shaped + ≈2.3k shapeless grid recipes, keyed by item *name*). BDS also registers recipes in code (colour dyeing, slabs, ...); the extractor reproduces them from explicit rules. A wire `CraftingData` capture is used only as an oracle (`--verify`: no aux-free grid recipe a stock BDS sends may be missing). An earlier iteration baked the capture itself into the data and carried 1557 recipes that could never match (`name:aux` strings), so it was dropped. `RecipeRegistry` resolves names against Zenith's palettes and fails the load on an unknown name. `RecipeRegistry` loads it and matches by bounding-box shape (with the mirror when `assume_symmetry`), item name and item tag (`ItemTags`, the twelve tags the data uses), and requires the grid to contain exactly the recipe's items. A craft request for more crafts than the grid affords is refused rather than reduced. `CraftingData` now sends shaped and shapeless recipes with name/tag descriptors, deterministic uuids and the data's own station; whether a recipe fits 2×2 is the client's call from its shape. Net ids are assigned in data order.

**Removed:** `recipes.nbt`, its embedded-resource test, and the `tools/gamedata-import` importer + tests (their only purpose was producing/validating that file). The brarchive reader's findings stay in ADR §142.

**Not done / limits:** recipes needing an item aux value (beds, banners, firework stars, tipped arrows, suspicious stew, maps: 458 on the wire — Zenith's `StackId` has no aux), output NBT, furnace/stonecutter/brewing/smithing stations are dropped by the extractor and counted; `CraftRecipeAuto` (recipe book) is still unsupported. Item tag membership is by name rules, verified only against the data's own references. Not validated with a retail client.
