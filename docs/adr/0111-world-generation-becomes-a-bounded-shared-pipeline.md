# ADR §111 — World generation becomes a bounded shared pipeline

> Part of the [decision log](README.md). Code and docs cite this record as `ADR §111`.

**Choice:** World generation uses a concrete per-world request broker with bounded worker
concurrency, deduplication by world identity/dimension/generator version/chunk, immutable shared
results, and per-session publication budgets. The GameLoop consumes completed results but never
waits for generation/I/O or drains an unbounded completion queue. The default generation worker
count is one; operators can raise it only through measured configuration.

**Why:** A client run showed 737 generated columns, roughly 118 seconds in payload generation and
a 1.36 second maximum `tick.system.chunk-stream` sample. The old `Parallel.ForEachAsync` fan-out
used `Environment.ProcessorCount`, and completed streams were drained without a per-tick bound.
That made CPU and synchronous packet encoding visible as tickrate stalls. Dragonfly's concrete
deduplicated request table and fixed worker pool provide the applicable reference pattern.

**Invariants:** one active generation per immutable world-generation key; cancellation only removes
the consumer wait; failed requests leave no permanent in-flight entry; generated bytes are shared
but publication remains session-owned; queue, retained bytes and publication are bounded and
diagnosed.

**Deferred:** a general scheduler/job system, global cross-world cache, plugin-facing generator
API, and changing the terrain algorithm or generator version without an explicit equivalence
fixture and migration decision.

See [`docs/adr/0111-world-generation-pipeline.md`](0111-world-generation-pipeline.md) and the
world-generation plan for the staged implementation and benchmark gates.
