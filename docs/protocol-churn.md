# Protocol churn checklist

**Last review:** 2026-10-12 — target is stable Bedrock 1.26.52 / protocol 2193. The Mojang 1.26.51 schema tag and Endstone protocol-docs r26_u5 (1.26.52.3) both identify stable protocol 2193. This update applies the v2193 `Hand` field to item-use transactions, reads AuthInput's required Input Data array directly, removes redundant Cereal accessor-presence bytes in InventoryTransaction and PlayerAuthInput decoding, writes the single optional-presence bytes required by ItemStackResponse, and updates `PlaySoundPacket`'s field order and optional fields. Endstone's version-aware `input.py`, `item_stack.py`, and `sound.py` schemas confirm the reviewed 2193 field gates. A follow-up login fix sends the StartGame `SpawnBiomeType::Default` enum instead of treating biome network IDs as that enum. The full solution suite passes (1407/1407); the focused StartGame wire test passes, and smoke-bot reaches `join`, `start_game`, and `spawn` against protocol 2193. The bot does not render the client UI, so the reported Bedrock error screen remains unverified in a graphical client. The 2193 changelog was checked against Zenith's implemented packet subset; unsupported packet payloads are not being claimed as implemented.

Cadence: ~trimestral, or whenever the team targets a newer Bedrock client. **Manual** — no remote schema scraper.

6. Update **Last review** date at the top of this file.

## 2026-10-11 implementation notes / 2026-10-12 reference review

- Stable client target is Bedrock 1.26.52 / protocol 2193. The supplied local Mojang docs are preview 1.26.60-beta.30 / 2225, so they were used for NetherNet guidance and cross-checked against the official stable 1.26.51 / 2193 packet pages and Endstone protocol-docs r26_u5 for protocol decisions.
- `InventoryTransactionPacket` now reads the transaction variant and action array directly, uses the request ID to determine legacy slot data, and reads the 2193 ItemUse `Hand` byte.
- `PlayerAuthInputPacket` reads the required Input Data array without an option byte, no longer consumes redundant Cereal accessor-presence bytes, and retains the real optional gates. Embedded transaction base actions and request-ID-conditioned legacy slots follow the schema order.
- `ItemStackResponsePacket` emits one presence byte for each optional field; the second, Cereal-generated byte was removed.
- `PlaySoundPacket` now follows the 2193 order: loop count, required bypass-listener-range boolean, optional server sound handle, optional playback-position float. The previous encoder omitted loop count and bypass; the packet tests cover both optionals present and absent.
- Endstone's versioned Python schema independently confirms the 2193 changes in `PlayerAuthInputPacket`/embedded ItemUse, `ItemStackResponseInfo`/slot info, and `PlaySoundPacket`. Endstone's protocol-docs README identifies r26_u5 / 1.26.52.3 as stable protocol 2193.
- The other stable 2193 deltas were checked against Zenith's packet call sites: `BuildPlatform` remains numeric value 7 for Nintendo; `StartGamePacket` omits the now-optional gathering configuration; enum-only additions need no payload change. The changed payloads for packets Zenith does not implement remain outside the supported packet subset.
- The updated unit tests cover the revised wire shape and offhand value decoding. `dotnet test zenith.sln -c Release` passed all 1407 tests, including the 1155 Zenith tests and 10 independent NetherNet tests; the StartGame-specific wire test also passed in isolation. The smoke-bot using the 1.26.51 schema for protocol 2193 received `join`, `start_game`, and `spawn` from Zenith 1.26.52. This proves the protocol join path reaches InGame, but it does not render the graphical Bedrock client or reproduce the reported error screen.

Automation against public schemas remains deferred (ARCHITECTURE freeze: no decorative infra).

## Stable data refresh (2026-10-12)

The embedded assets now come from official BDS 1.26.52.3, queried through Endstone 0.11.13: 22,091 validated block states, 2,076 items, 78 non-empty component definitions, 1,980 creative reference entries and 89 biomes. The existing ItemRegistry serializer preserves those definitions; it formerly emitted empty NBT for every item. No new packet was introduced. Source archive and asset hashes are recorded in `src/zenith/data/manifest.json`; the offline workflow is documented in `tools/bedrock-data/README.md`.

Full solution: 1407 tests passed. The smoke-bot reached join/start_game/spawn using a new temporary world on UDP 19147; Zenith logged the InGame transition. A second login capture matched all item registry fields and typed NBT against BDS after sorting entries by name, and the biome body matched byte for byte. CreativeContent remains the intentional curated runtime subset. The bot does not render the graphical client; the reported error screen remains unverified there.

Rollout uses fresh world and player files by operator choice. Stored numeric IDs from previous palettes are not migrated. NetherNet framing/signaling moved to the independent Zenith.NetherNet package with its own tests; its WebRTC/session adapter remains pending. Existing configs selecting NetherNet now log a warning and use RakNet to preserve Bedrock login.
